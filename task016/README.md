# Task 016 — Two-endpoint field link harness

**Scope:** Experimental, authenticated store-and-forward TCP link over any IP path. Reuses `task012.transport`. It does **not** establish that traffic uses satellites, does not secure the transport against traffic analysis, and does not replace CometBFT P2P. No actual satellite hardware has been tested.

## Local demonstration

Install `cryptography` as already required by Task 012. From repository root:

```bash
python -m unittest discover -s task016 -p 'test_*.py' -v
python task016/field_link.py keygen /tmp/kaspyra-sender.key
# Copy the printed public key into /tmp/kaspyra-allowlist.txt (one hex key per line).
python task016/field_link.py listen /tmp/kaspyra-in.db /tmp/kaspyra-allowlist.txt --host 127.0.0.1 --port 18716
# In another shell:
printf 'example' > /tmp/kaspyra-payload.bin
python task016/field_link.py queue /tmp/kaspyra-out.db /tmp/kaspyra-sender.key /tmp/kaspyra-payload.bin
python task016/field_link.py transmit /tmp/kaspyra-out.db --host 127.0.0.1 --port 18716
```

For a two-machine field test, bind the receiver to its **private VPN interface address** and transmit to that address. Do **not** expose this unauthenticated TCP listener directly to the public internet. Use a properly configured encrypted VPN or TLS tunnel and firewall; the signed envelopes authenticate senders but do not encrypt payloads. Never put private keys in the repository.

To submit a valid **signed KASPYRA transaction** to a local CometBFT RPC, optionally run the receiver with `--rpc-url http://127.0.0.1:26657` and queue the exact signed transaction bytes generated by the existing ledger. The receiver persists the verified payload before RPC submission. An RPC response is **not finality**: independently query transaction inclusion, result code, height and validator convergence. RPC errors require operator inspection/retry; the current inbox is not an automatic reliable RPC retry queue. Never expose RPC externally.

## Field evidence checklist

- Terminal and service provider model, account routing mode, ground gateway dependencies and documented end-to-end route.
- Physical terminal location and endpoint connection type, independently recorded (do not publish precise coordinates without consent).
- Sender and receiver clocks synchronized, terminal service status, observed RTT and bytes per signed envelope.
- Repeated tests with interruption and recovery; preserve JSON output, node logs and chain transaction receipt.
- Provider statement on public internet transit and whether the path is actually satellite-only.

**GO for field testing:** two endpoints exchange authenticated messages, recover after outage, and persist received bytes. **NO-GO for satellite-only claim:** absent independently verifiable provider path evidence. **NO-GO for production:** no TLS, admission limits, queue quotas, replay/expiry policy review, and independent security audit.
